# Plano: exclusão de clipes acessível — botão no topo + exclusão individual por clipe

## Problema (causa raiz confirmada)

O botão "Excluir selecionados" vive na `BarraAcaoInferior` (`src/components/BarraAcaoInferior.tsx:27`), que é `fixed bottom-0 z-40` — mas a TabBar do Layout (`src/routes/Layout.tsx:269-272`) também é `fixed bottom-0 z-40` e vem **depois** no DOM. Com z-index empatado, a TabBar cobre a barra de ação, e os toques nunca chegam ao botão. `/clipes/admin/repositorio` não é "fluxo focado" (o regex de `Layout.tsx:110` só casa rotas de partida), então a TabBar fica visível. É o único uso de `BarraAcaoInferior` fora de fluxo focado — os demais (PartidaNova, Votar, AoVivo etc.) rodam com TabBar oculta.

## Solução

Mover a ação de excluir para o **topo da lista** (como pedido) e adicionar **exclusão individual no card de cada clipe**. Reuso total do fluxo existente (edge function `admin-excluir-clipes` já aceita 1–500 ids — exclusão individual é um lote de 1). **2 arquivos, zero mudança de backend/lib.**

### 1. `src/routes/ClipesRepositorio.tsx`

- **Botão no topo**: mover o `Botao variante="perigo" larguraCompleta` (Trash2 + `Excluir selecionados (N)`) para logo abaixo da linha do contador + "Marcar todos/Limpar" (`:240-262`), dentro do bloco `clipes.length > 0`. A legenda "A exclusão é definitiva: os vídeos saem do ar." vira um texto pequeno (`text-giz-fraco`) sob o botão.
- **Remover a `BarraAcaoInferior`** (bloco `:275-287` + import `:13`) e o `pb-28` do container (`:190`) — o `main` do Layout já tem `pb-16` de folga.
- **Exclusão individual**: trocar `confirmacaoAberta: boolean` por `idsPendenteExclusao: number[] | null`. O botão do topo abre com `[...selecionados]`; o botão do card abre com `[clipe.id]`. `confirmarExclusao` passa a usar esses ids (snapshot local, como hoje).
- Após sucesso, filtrar do `selecionados` apenas os ids excluídos (em vez de limpar tudo sempre) — preserva marcações quando a exclusão individual é de um clipe não marcado; exclusão em lote continua limpando tudo.
- Mensagem do `ConfirmDialog`: singular quando 1 id ("Excluir este clipe? O vídeo sai do ar definitivamente."), plural como hoje. Snackbar inalterada (já usa `resultado.excluidos`).
- Passar para a grade: `onExcluirClipe={(id) => setIdsPendenteExclusao([id])}` e `desabilitarExclusao={excluindo}`.

### 2. `src/components/GradeClipesPartida.tsx`

- Novas props opcionais, espelhando o padrão das props de seleção (`:15-23`) — **sem elas o modo leitura de `PartidaDetalhe` não muda em nada**:
  - `onExcluirClipe?: (clipeId: number) => void` — ausente = não renderiza o botão.
  - `desabilitarExclusao?: boolean` — congela durante a exclusão (espelho do `desabilitarSelecao`).
- Botão por item no grupo de ações (ao lado de Baixar/Compartilhar, `:109-132`): **ícone-only `Trash2`** com alvo 44x44, `aria-label`/`title` `Excluir clipe N`, estilo compacto dos irmãos (`px-3 py-2 rounded-[4px] border...`) com cores de perigo do design system (`border-perigo bg-perigo text-branco-time hover:brightness-110`, mesmas classes da variante perigo de `Botao.tsx:22`).
  - Ícone-only porque "Baixar" + "Compartilhar" + "Excluir" com texto não cabem nos ~336px úteis de um mobile 360px; lixeira é universal para ação destrutiva.
- Adicionar `flex-wrap` ao rodapé do item (`:81`) como rede de segurança para telas estreitas.

## Decisões assumidas (ajuste se discordar)
